## Intended runtime flow

1. Confirm Rekongpiled really accepted the unchanged US retail ROM. The existing [RA game hash page](https://retroachievements.org/game/10075/hashes) lists MD5 `9ec41abf2519fc386cadd0731f6e868c`. The optional local `rom_hash_check` uses official `rcheevos` N64 hashing, including byte-order normalization. A Windows local copy matched. Both modes hash the game's stored `DK64.z64` before login and reject a mismatch; Windows resolves portable installs beside the executable and standard installs under `%LOCALAPPDATA%\DK64Recompiled`, with separate missing-file and wrong-hash statuses. This is not yet proof that the *actual bytes selected by the game process* were that same file; a release must bind identity to the active ROM.
2. The Windows bridge uses `CredUIPromptForCredentialsW` without password persistence, official `rc_client` login, and WinHTTP HTTPS to exactly `retroachievements.org:443` with redirects disabled. The opt-in Save checkbox in the sign-in dialog stores only the RA login token in a per-user, local-machine generic credential; future Online launches use `rc_client_begin_login_with_token`. Local mode does not read or clear a remembered token; F8 > Account > Log Out removes the mod-specific credential, ends the RA session, and resumes cached guest tracking. A successful manual sign-in with Save unchecked clears an older token; canceling does not clear it. An invalid saved token asks for manual login; transport or other sign-in failures fall back to the guest cache. The existing credential key retains the legacy `_preview_v1` suffix so previously saved tokens keep working. Do not log either token or password. Offline account tests cover token fallback, cancellation, storage failures, logout, preservation of local history, and cached-set fallback. Live auth timing, transport retries, and shutdown still need broader validation. Authenticated requests block the game thread and must be made asynchronous before release.
3. Map RA physical N64 RAM addresses `0x000000`–`0x7fffff` to Rekongpiled's RDRAM. The recompiler stores 32-bit words in host little-endian layout: game-side `MEM_B` uses an address XOR `3`. The existing RA N64 set, however, references raw word-swapped emulator byte positions. An offline run counted the game-state `2` at raw `0x755317` but at normalized `0x755314`, and saw the rap timer changing at the host position corresponding to raw `0x75531E`; the prior normalized reader saw neither official condition. `MemoryView::read` now returns raw RDRAM bytes, with partial reads at the RAM boundary and no out-of-bounds access. The bridge supplies this reader to `rc_client`. A live DK Rap Preview trigger passed after this correction; broader parity against a supported emulator remains required.
4. After login and identification, `rc_client_begin_load_game` checks game ID `10075`, then `rc_client_do_frame` evaluates from the game loop. The successful, validated `achievementsets` response is stored locally by verified ROM hash; no response or trigger definition is distributed with the mod. In guest mode, `rc_runtime` activates cached core definitions and evaluates game RAM without logging in or making award requests. A missing/corrupt cache fails closed with an explicit browser status. Online starts a softcore server session with spectator off, then enables awards only after the correct game ID and safe mode state are confirmed. The transport also denies Hardcore `h=1`, mismatched-hash and invalid-ID award POSTs and all leaderboard submissions. It observes the official award response to distinguish **Unlocked on RA** from local/unconfirmed triggers. Eleven Windows offline tests, including guest no-login evaluation, request gating, acknowledgement parsing, and generated sound validation, pass. The live DK Rap Online trigger returned a confirmed softcore award for ID `60497`; the browser's RA count rose from zero to one. The award is worth zero points. The server-injected zero-point `Warning: Unknown Emulator` item was classified separately. The Windows DLL writes our diagnostic lines to `mods/dk64_ra_probe.local.log`, without credentials, tokens, or RAM contents. Confirm other achievement memory parity and exactly once per simulated frame, not per display refresh; handle pause/idle and resets.
5. The browser shows the live RA username or **RA: not signed in**, set-load status, server-confirmed unlocks, locally stored or unconfirmed triggers and current-session measured progress, in a 16-column badge grid with All / Locked / Unlocked filters and a shared detail card. Hover, arrow keys, D-pad and left stick select badges; Enter / A activates controls, Tab changes sections, Home / End moves to the first / last badge, and sets larger than 144 badges scroll by row. The built-in mod Configure screen renders static manifest options before gameplay and has no supported runtime write API for a live username, so the option's description directs users to F8. The visible badge grid and toasts request public badge art on a background thread from an exact RA media-host/path allowlist; malformed/oversized/failed images remain placeholders. A bounded toast queue shows each trigger for about eight seconds with its unlocked badge, title, and description only; it plays an original synthesized wood-percussion/marimba cadence when presented. The sound can be disabled in mod config; no copyrighted game recording is bundled. A centered Reset modal has Cancel and Confirm reset; Cancel was verified in-game without clearing the previously tracked DK Rap. Confirm reset was not invoked in-game. F8 toggles the browser; controller shortcuts need physical testing. Rekongpiled 1.0.2 does not dispatch queued mod hover/focus callbacks, so the browser observes SDL input through the native companion while its context captures game input. Shared DP geometry keeps pointer hit testing aligned after resizing; navigation has held-direction repeat and clears on focus loss, controller removal, closure and reset-modal transitions. The reset modal retains built-in radio controls polled each frame. Image slots are keyed by achievement ID plus unlock state, and at most four PNGs are decoded per frame. Reset persists an empty local record for the current account or Guest profile and verified ROM; it cannot change server unlocks or DK64 saves. Condition hit counters are not restored across launches, since they are not bound to an exact gameplay/save state. Full connection recovery, server-error and leaderboard display, and nonblocking authenticated HTTP remain future work.
6. Local trigger IDs are atomically written to `%LOCALAPPDATA%\Nikamimi\DK64RekongRetroAchievements\` in a versioned, bounded file keyed by RA username or `Guest` and supported ROM hash. An invalid file fails closed without overwriting it. Progress writes do not contain credentials, trigger definitions, or RAM. The separate locally cached set JSON contains RA's game definitions for this device only and must never be bundled or committed; it may become stale until Online refreshes it. Reset confirmation clears only the current profile's local trigger history; server account unlocks remain. Unit tests cover restart persistence, account/ROM isolation, reset and corrupt-file preservation. Online uses rcheevos' in-session retry behavior, but there is no durable offline/cross-restart award queue; an unconfirmed local trigger is not automatically replayed to the server. Confirm reset needs live QA before wider distribution.
7. Disable Hardcore during development. Audit pause, frame advance, save-state equivalents, cheats, gameplay-changing mods, speed changes, and the host's default enhancements before considering Hardcore. Do not enable it merely because the `rcheevos` API allows it.

Badge-grid UI verification (2026-09-26): Windows in-game checks covered the 128-badge cached set, pointer hover, arrow-key navigation, All / Unlocked filtering, reset Cancel, and window resizing. Windows offline tests passed 12/12 and Linux 13/13, including SDL keyboard, pointer, D-pad and stick event tests. Physical-controller navigation and native Linux gameplay still need hands-on validation.

## Verification needed before sharing as RA support

Linux work as of this revision: the x86-64 `.so` compiles on Ubuntu/WSL with libcurl and SDL2, and twelve offline tests pass, including Linux path, no-token, headless fallback, and native export/load checks. Linux follows the game's portable working directory, `APP_FOLDER_PATH`, or `~/.config/DK64Recompiled` to hash the stored ROM; it keeps local progress/cache under `XDG_DATA_HOME` or `~/.local/share`. Online can use a desktop kdialog/zenity prompt without putting credentials in argv, but token persistence is disabled on Linux. This is source/build validation, **not** an in-game Linux loader test, GUI sign-in test, or server award proof. See [Linux development notes](linux-development.md).

- The Windows 1.0.2 init/first-frame loader test passed. Confirm frame cadence and game-memory parity, then repeat on Linux/Steam Deck (and macOS if supported). The `.nrm` and native library must be installed side by side; the in-game `.nrm` installer alone does not copy the sibling native file.
- Verify the retail ROM's canonical MD5, actual RA game ID `10075`, loaded achievement count, and memory values/trigger transitions against an officially supported N64 emulator. Cover new game, existing save, map changes, pause, reboot, disconnect/retry, and simultaneous mods.
- Saved-token login, set load, local DK Rap trigger, browser, and reset Cancel passed in the local build. A later Online run confirmed DK Rap `60497` server-side with the badge toast and jingle start; verify other triggers, reset Confirm, spectator/no-submit mode, and a unique user agent without impersonating an approved emulator. The `Unknown Emulator` warning is expected until RA recognizes this client. The owner approved v0.2.2 publication after the final Windows test; do not claim broader parity or points earned on the basis of the zero-point DK Rap test. Confirm memory parity, offline queueing, lifecycle and client/compliance expectations with the maintainers before public release.
- Package platform-specific native binaries with their licenses, scan for accidentally committed ROMs/credentials, and document safe updates/uninstall.
