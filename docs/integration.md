# Integration contract and release gates

Research snapshot: 2026-09-23. Rekongpiled tag `1.0.2` has `recomp_on_init` and `dk64recomp_every_frame` in `patches/boot_logos_patches.c`; the latter runs inside the game's main loop. Its runtime's `librecomp` loader reads the `native_libraries` manifest field, resolves the library alongside the `.nrm`, and imports functions from the special `.` (self) dependency. The source defaults to Online softcore beta and falls back to no-login Local Tracking only when a validated DK64 set has already been cached on the PC. Ten offline tests pass. A saved-token local session loaded game `10075`, showed the browser, and wrote DK Rap to the per-user file; after a restart its row persisted and the reset modal's Cancel path preserved it. A later live Online session received a server-confirmed softcore unlock for DK Rap `60497` (0 points), showed the colored badge toast, started the jingle, and displayed **Unlocked on RA** in the browser. An Online session on the updated build cached the 128-core set; a subsequent Local Tracking session loaded all 128 without signing in, even though a token remained saved. **Confirm reset, broader parity, and a points-earning achievement remain unverified.** The owner reports Discord approval for limited hook-only testing, not formal certification or broad publication.

## Intended runtime flow

1. Confirm Rekongpiled really accepted the unchanged US retail ROM. The existing [RA game hash page](https://retroachievements.org/game/10075/hashes) lists MD5 `9ec41abf2519fc386cadd0731f6e868c`. The optional local `rom_hash_check` uses official `rcheevos` N64 hashing, including byte-order normalization. A Windows local copy matched. Both modes hash the portable install's `DK64.z64` before login and reject a mismatch. This is not yet proof that the *actual bytes selected by the game process* were that same file; a release must bind identity to the active ROM.
2. The Windows bridge uses `CredUIPromptForCredentialsW` without password persistence, official `rc_client` login, and WinHTTP HTTPS to exactly `retroachievements.org:443` with redirects disabled. The opt-in Remember setting stores only the RA login token in a per-user, local-machine generic credential; future Online launches use `rc_client_begin_login_with_token`. Local mode does not read or clear a remembered token; disabling Remember removes the mod-specific credential. An invalid saved token asks for manual login; transport or other sign-in failures fall back to the guest cache. The existing credential key retains the legacy `_preview_v1` suffix so previously saved tokens keep working. Do not log either token or password. Invalid-token fallback, timing, failures, retries, and shutdown still need dedicated tests. Authenticated requests block the game thread and must be made asynchronous before release.
3. Map RA physical N64 RAM addresses `0x000000`–`0x7fffff` to Rekongpiled's RDRAM. The recompiler stores 32-bit words in host little-endian layout: game-side `MEM_B` uses an address XOR `3`. The existing RA N64 set, however, references raw word-swapped emulator byte positions. An offline run counted the game-state `2` at raw `0x755317` but at normalized `0x755314`, and saw the rap timer changing at the host position corresponding to raw `0x75531E`; the prior normalized reader saw neither official condition. `MemoryView::read` now returns raw RDRAM bytes, with partial reads at the RAM boundary and no out-of-bounds access. The bridge supplies this reader to `rc_client`. A live DK Rap Preview trigger passed after this correction; broader parity against a supported emulator remains required.
4. After login and identification, `rc_client_begin_load_game` checks game ID `10075`, then `rc_client_do_frame` evaluates from the game loop. The successful, validated `achievementsets` response is stored locally by verified ROM hash; no response or trigger definition is distributed with the mod. In guest mode, `rc_runtime` activates cached core definitions and evaluates game RAM without logging in or making award requests. A missing/corrupt cache fails closed with an explicit browser status. Online starts a softcore server session with spectator off, then enables awards only after the correct game ID and safe mode state are confirmed. The transport also denies Hardcore `h=1`, mismatched-hash and invalid-ID award POSTs and all leaderboard submissions. It observes the official award response to distinguish **Unlocked on RA** from local/unconfirmed triggers. Ten offline tests, including guest no-login evaluation, request gating, acknowledgement parsing, and generated sound validation, pass. The live DK Rap Online trigger returned a confirmed softcore award for ID `60497`; the browser's RA count rose from zero to one. The award is worth zero points. The server-injected zero-point `Warning: Unknown Emulator` item was classified separately. The Windows DLL writes our diagnostic lines to `mods/dk64_ra_probe.local.log`, without credentials, tokens, or RAM contents. Confirm other achievement memory parity and exactly once per simulated frame, not per display refresh; handle pause/idle and resets.
5. The browser shows the live RA username or **RA: not signed in**, set-load status, server-confirmed unlocks, locally stored or unconfirmed triggers and current-session measured progress, with built-in radio filters and a page slider. The built-in mod Configure screen renders static manifest options before gameplay and has no supported runtime write API for a live username, so the option's description directs users to F8. The six visible entries and toasts request public badge art on a background thread from an exact RA media-host/path allowlist; malformed/oversized/failed images remain placeholders. A bounded toast queue shows each trigger for about eight seconds with its unlocked badge, title, and description only; it plays an original synthesized wood-percussion/marimba cadence when presented. The sound can be disabled in mod config; no copyrighted game recording is bundled. A centered Reset modal has Cancel and Confirm reset; Cancel was verified in-game without clearing the previously tracked DK Rap. Confirm reset was not invoked in-game. F8 toggles the browser; controller shortcuts need physical testing. A one-option radio is used as a button, and modal options are polled each frame, because Rekongpiled 1.0.2 does not dispatch queued mod button callbacks. Reset persists an empty local record for the current account or Guest profile and verified ROM; it cannot change server unlocks or DK64 saves. Condition hit counters are not restored across launches, since they are not bound to an exact gameplay/save state. Full connection recovery, server-error and leaderboard display, and nonblocking authenticated HTTP remain future work.
6. Local trigger IDs are atomically written to `%LOCALAPPDATA%\Nikamimi\DK64RekongRetroAchievements\` in a versioned, bounded file keyed by RA username or `Guest` and supported ROM hash. An invalid file fails closed without overwriting it. Progress writes do not contain credentials, trigger definitions, or RAM. The separate locally cached set JSON contains RA's game definitions for this device only and must never be bundled or committed; it may become stale until Online refreshes it. Reset confirmation clears only the current profile's local trigger history; server account unlocks remain. Unit tests cover restart persistence, account/ROM isolation, reset and corrupt-file preservation. Online uses rcheevos' in-session retry behavior, but there is no durable offline/cross-restart award queue; an unconfirmed local trigger is not automatically replayed to the server. Confirm reset needs live QA before wider distribution.
7. Disable Hardcore during development. Audit pause, frame advance, save-state equivalents, cheats, gameplay-changing mods, speed changes, and the host's default enhancements before considering Hardcore. Do not enable it merely because the `rcheevos` API allows it.

## Verification needed before sharing as RA support

Linux work as of this revision: the x86-64 `.so` compiles on Ubuntu/WSL with libcurl and SDL2, and twelve offline tests pass, including Linux path, no-token, headless fallback, and native export/load checks. Linux follows the game's portable working directory, `APP_FOLDER_PATH`, or `~/.config/DK64Recompiled` to hash the stored ROM; it keeps local progress/cache under `XDG_DATA_HOME` or `~/.local/share`. Online can use a desktop kdialog/zenity prompt without putting credentials in argv, but token persistence is disabled on Linux. This is source/build validation, **not** an in-game Linux loader test, GUI sign-in test, or server award proof. See [Linux development notes](linux-development.md).

- The Windows 1.0.2 init/first-frame loader test passed. Confirm frame cadence and game-memory parity, then repeat on Linux/Steam Deck (and macOS if supported). The `.nrm` and native library must be installed side by side; the in-game `.nrm` installer alone does not copy the sibling native file.
- Verify the retail ROM's canonical MD5, actual RA game ID `10075`, loaded achievement count, and memory values/trigger transitions against an officially supported N64 emulator. Cover new game, existing save, map changes, pause, reboot, disconnect/retry, and simultaneous mods.
- Saved-token login, set load, local DK Rap trigger, browser, and reset Cancel passed in the local build. A later Online run confirmed DK Rap `60497` server-side with the badge toast and jingle start; verify other triggers, reset Confirm, spectator/no-submit mode, and a unique user agent without impersonating an approved emulator. The `Unknown Emulator` warning is expected until RA recognizes this client. Limit the current softcore beta to owner-approved private testers; do not publish broadly or claim points earned on the basis of the zero-point DK Rap test. Confirm memory parity, offline queueing, lifecycle and client/compliance expectations with the maintainers before public release.
- Package platform-specific native binaries with their licenses, scan for accidentally committed ROMs/credentials, and document safe updates/uninstall.
